# EL BEM BEAUTY — запуск на бесплатном Firebase Spark

## Что сохраняется в интернете
Firebase Authentication: аккаунты клиентов и пароль администратора.
Firestore: товары, категории, услуги, мастера, тексты, расписание, заблокированное время,
записи, статусы, заказы и отзывы. База одна для всех устройств.

Фотографии и музыка: обычные публичные HTTPS-ссылки, либо файлы внутри `public`.
Firestore хранит **адрес** файла, но не содержимое загружаемого файла.
Для нового фото/аудио, которого ещё нет в интернете, добавьте файл в папку `public`
(например, `public/images/master.jpg` или `public/music.mp3`), используйте ссылку
`/images/master.jpg` или `/music.mp3` и заново опубликуйте сайт на Vercel.
Владелец может выбирать уже опубликованные фотографии и менять их ссылки в админке.
Загрузка нового файла с компьютера напрямую через админку на Spark недоступна.

## Ваша текущая настройка уже сохранена
- Firebase-проект `el-bem-beauty` и тариф Spark: ничего создавать заново не надо.
- Authentication Email/Password: включён.
- Firestore `(default)`: создан.
- Вы уже назначили администратору роль через `grant-admin.cjs`.
- Ваш `.env.local` содержит нужные публичные параметры и VITE_ADMIN_LOGIN_EMAIL.
- **Не стирайте `.env.local`**, **не вставляйте пароль в сайт** и **не передавайте JSON-ключ**.

## Что сделать по порядку

### 1. Обновить код
Откройте в VS Code терминал в КОРНЕ проекта, рядом с `package.json`.
Скопируйте `EL_BEM_SPARK_ONLY.patch` туда и выполните:

```
git apply --check EL_BEM_SPARK_ONLY.patch
git apply EL_BEM_SPARK_ONLY.patch
```

Патч рассчитан на версию `EL_BEM_BEAUTY_FIREBASE_FINAL_UI_2026_10_22.zip`
с уже применённым `EL_BEM_ADMIN_PASSWORD_ONLY.patch`.
Он **не затрагивает `.env.local`**.

### 2. Опубликовать НОВЫЕ правила
Firebase Console -> Firestore -> вкладка Rules.
В VS Code откройте `firestore.rules`, скопируйте ВЕСЬ код и замените правила в Firebase.
Нажмите Publish. Старые правила из версии с Cloud Functions НЕ подойдут.
**Не делайте `allow read, write: if true`.**

### 3. Один раз загрузить каталог в Firestore
В терминале VS Code перейдите в папку `functions`:

```
cd functions
node scripts/seed-demo.cjs
```

Вы уже установили зависимости `functions` и настраивали переменные
`GOOGLE_CLOUD_PROJECT` и `GOOGLE_APPLICATION_CREDENTIALS` при `grant-admin.cjs`.
Если открыли новый терминал, эти переменные нужно повторно выставить.
`GOOGLE_CLOUD_PROJECT` должен быть `el-bem-beauty`, а `GOOGLE_APPLICATION_CREDENTIALS`
— путь к скачанному JSON-файлу в Downloads (ФАЙЛ НЕ КОПИРОВАТЬ В ПРОЕКТ).

Скрипт добавляет только **отсутствующие** документы, не затирая существующие.
Проверьте в Firestore -> Data коллекции: `services`, `masters`, `products`,
`categories`, `siteContent`. Начальные данные из каталога — пример для первого запуска;
для реального салона цены и названия нужно проверить в админке.

### 4. Проверить сайт локально
В Firebase Console -> Authentication -> Settings -> Authorized domains добавьте
`localhost` для локальной разработки, если его нет (у новых проектов он обычно не добавлен автоматически).
После публикации Vercel проверьте также домен Vercel.

Вернитесь в корень проекта:

```
cd ..
npm run typecheck
npm run build
npm run dev
```

В Firefox/Chrome откройте выданный Vite адрес. Проверьте:
1. Регистрация нового клиента email+пароль (НЕ под админским email).
2. Запись на услугу: выбор даты и свободного времени, отправка заявки.
3. Откройте сайт в другом браузере: занятый интервал не должен предлагаться.
4. Вход в `/admin` по паролю администратора (технический email уже в `.env.local`).
5. В «Записи» заявка появляется; подтвердите/отмените. Отмена должна вернуть интервал.
6. Измените цену товара; после обновления на другом устройстве она меняется.
7. Оформите заказ; он появляется в «Заказы».
8. Настройте URL публичной фотографии/музыки; убедитесь, что URL доступен со второго устройства.

Если Firestore показывает `Missing or insufficient permissions`, проверьте,
что были опубликованы именно новые `firestore.rules`, а текущий аккаунт клиента
зарегистрирован, админ назначен и заново вошёл после назначения роли.

### 5. GitHub + Vercel
Залейте исходный проект на GitHub БЕЗ `.env.local`, `node_modules` и JSON-ключа.
На Vercel выберите репозиторий, Framework Preset **Vite**,
Build Command **npm run build**, Output Directory **dist**.
В Vercel -> Project -> Settings -> Environment Variables добавьте все
`VITE_FIREBASE_*` из `.env.local` и `VITE_ADMIN_LOGIN_EMAIL`.
В Firebase Authentication -> Settings -> Authorized domains добавьте реальный домен Vercel
(например, `example.vercel.app`), затем новый деплой.
Регистрация клиентов и админ-вход по Firebase не требуют платного тарифа.

## Ограничения бесплатной архитектуры
- Cloud Functions не используются; серверное выполнение `functions/index.js` НЕ нужно.
- Клиенту нужно войти перед созданием записи, заказа или отзыва.
- Двойную запись на одно время исключают атомарные блокировки по 30 минут
  в Firestore. Расписание и стоимость считаются по каталогу в клиенте;
  администратор подтверждает заявку и итоговую стоимость до обслуживания.
- Общая длительность одной записи ограничена 4 часами, а один заказ содержит до
  8 разных товаров, максимум 20 единиц каждого.
- Без серверного backend нет полноценной антиспам/проверки сложной бизнес-логики.
  Для небольшого салона используйте ручное подтверждение записи и заказа.
- Фотографии/музыку без отдельного хранилища нельзя произвольно загружать в админке
  и сразу показывать всем. Изменяемые URL изображений в Firestore работают.
- В браузерах автозапуск звука может быть заблокирован до первого действия пользователя.
- Отдельный платёжный сервис не подключён. Заказ фиксируется, но **не означает оплату**.
- При превышении бесплатных квот Spark база может временно перестать обслуживать запросы.
