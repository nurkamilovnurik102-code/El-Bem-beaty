# Архитектура и защита — EL BEM BEAUTY 2.0

## Технологии

React/Vite/TypeScript + React Router + react-i18next, Firebase Auth, Firestore, Firebase Storage, Cloud Functions v2, Vercel SPA. Старой зависимости Supabase в рабочей архитектуре нет. `src/store.ts` — единая граница работы с данными; `src/firebase.ts` — клиентская инициализация.

## Коллекции Firestore

| Коллекция | Содержимое | Доступ с браузера |
|---|---|---|
| `siteContent/main` | Hero, контакты, галерея, фото, музыка | Публичное чтение, админ-запись |
| `services` | Название, цена, длительность, описание, статус | Публичное чтение, админ-запись |
| `categories` | Категории магазина и услуг | Публичное чтение, админ-запись |
| `masters` | Мастера, специализация, список serviceIds | Публичное чтение, админ-запись |
| `products` | Товары, цены, категории | Публичное чтение, админ-запись |
| `masterHours` | День недели, смена каждого мастера | Только админ |
| `blockedSlots` | Отдельные исключённые интервалы | Только админ |
| `bookings` | Данные клиента, выбранные услуги/дата/время, статус | Админ или создавший запись зарегистрированный пользователь; запись через Cloud Functions |
| `orders` | Покупатель, снимок состава/цен, сумма, статус | Админ или владелец заказа; создание через Cloud Functions |
| `reservationLocks` | Занятые 15-минутные отрезки для мастера/даты | Только сервер |
| `reviews` | Имя, текст, рейтинг, статус публикации | Публично только подтверждённые, админ — все |
| `users` | Зарезервировано для клиентского профиля | Свой профиль или админ |

**Стабильные идентификаторы:** ссылки на услуги и мастеров хранятся по ID; заказы содержат копию стоимости и названия товара, поэтому изменение каталога не меняет прошлые заказы. Администратор задаётся **custom claim `admin: true`**, который присваивается только Firebase Admin SDK на доверенном устройстве. Публичный сайт не может сам назначить себе администратора.

## Запись клиента

1. В браузере клиент выбирает одну/несколько услуг, мастера или «Любой свободный», дату и время.
2. `availableSlots` сверяет реальную продолжительность, графики, закрытые интервалы и блокировки в Firestore. Отображается доступное время.
3. При отправке `createBooking` снова загружает **актуальные** цены, длительности, специализации и рабочее время с сервера.
4. В Firestore transaction создаются `bookings/<id>` и блокировки `reservationLocks/<master>|<day>|<15-min-slot>`. При конкурентной заявке на то же время операция конфликтует, вторая не подтверждается. Для выбора «Любой мастер» пробуются подходящие мастера.
5. Статус изначально `pending`; администратор `confirmed`/`cancelled` меняет только через callable `updateBookingStatus`. Отмена удаляет относящиеся к заявке блокировки.
6. Если пользователь вошёл через Firebase Auth, его UID записывается в заказ или бронирование. Гостевые заявки доступны администратору, но не появляются в личном кабинете, поскольку у гостя нет UID.

Основной часовой пояс **Asia/Bishkek (UTC+6)**, шаг выбора времени 30 минут; сервер бронирует пересечения по 15-минутным интервалам. Демонстрационное расписание без явно заданных часов предполагает 09:00–19:00; владельцу необходимо настроить реальные часы.

## Покупки

Cloud Function `placeOrder` самостоятельно проверяет количество, наличие и **цену товаров из Firestore**, сохраняет снимок позиций, итог, контактные данные и статус `pending`. В браузере после подтверждённого сохранения открывается WhatsApp либо Telegram (там клиент вручную отправляет текст). Онлайн-оплаты в проекте нет. Статус заказа владелец меняет через отдельную административную Cloud Function.

## Отзывы

Только вошедшие пользователи могут предложить отзыв через `submitReview`. Он сохраняется как `approved: false` и не показывается публично до модерации в админке. Проверка оценок — 1–5.

## Ограничения и обязательная защита перед production

- Реальное развертывание, правила Firestore/Storage, клиентская Auth и клиентские/админские сценарии необходимо проверить против **настоящего** Firebase, а не только моков.
- Cloud Functions в демонстрационной конфигурации принимают гостевые заявки. Для реальных клиентов настройте App Check, ограничения частоты запросов, мониторинг и защиту от массовых заявок. App Check сам по себе не заменяет rate limiting.
- Загрузка JPG/PNG/WebP/GIF/AVIF ограничена 10 МБ при подключенном Storage, аудиофайлы — 20 МБ. Правила не обеспечивают антивирусную проверку или автоматическое удаление неиспользуемых файлов.
- Ролевые права и коды ошибок не заменяют полноценные юридические документы о сборе персональных данных и согласие клиентов.
- Атомарность проверена в локальном модульном тесте с имитацией транзакций, но не нагрузочным тестом в Firestore.
- Конфликт изменения расписания администратором и создания записи требует дополнительного реального интеграционного тестирования.
